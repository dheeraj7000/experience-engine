Experience Engine

A continual-learning architecture that transforms agent trajectories into validated, reusable competence.

Current agents treat the past as context.
The Experience Engine treats the past as training signal.

View on GitHub Get Started

The Problem

Memory (Today)

Past → Store → Retrieve → Use

Agents remember what happened but don't improve from it. The same mistakes repeat.

Experience (This Project)

Record → Evaluate → Diagnose → Induce → Validate → Policy

Agents learn from trajectories — extracting validated lessons, compiling skills, and updating behavioral policies.

The Experiment

Same model. Same tools. Same environment. Only the persistence layer changes.

A0

Stateless

Today's default agent. Records episodes for measurement only — injects nothing, learns nothing.

NoPersistence
A1

Memory-Only

Reflexion / ExpeL class. RAG over past episodes + shallow reflections. Helps modestly, then plateaus.

MemoryOnly
A2

Experience Engine

Full MVES loop: cluster → diagnose → induce → validate on held-out → compile skill → update policy.

ExperienceEngine

The central question: Does A2 show a steeper success curve than A1, with fewer repeated failures — net of overhead?

Implementation Phases

1

Minimal Engine

Episode recorder, outcome evaluator, experience schema, basic retrieval, validation gate, policy registry.

2

Causal Diagnosis

Failure taxonomy, trace debugger with CausalChain, feature-based clustering, contradiction mining.

3

Experience Graph

Typed graph store, automatic construction, similarity/transfer edges, hybrid multi-signal retriever.

4

Skill Compilation

Workflow induction from successes, preconditions/postconditions, validation, versioning.

5

Policy Management

Conflict detection/resolution, scope refinement, versioning, rollback, safety gating.

6

Forgetting & Governance

Confidence decay, staleness detection, audit logging, sensitive content blocking, human review.

7

Exploration & Internalization

Diversity scoring, exploration suggestions, internalization-worthiness scoring for candidate selection.

Task Families

All rewards are execution-grounded — run the tests, not an LLM judge.

🐛

Bug Reproduction

Write a test that reproduces a reported bug. Graded: fails on buggy code AND passes on fixed reference.

7 train + 2 held-out
🎲

Flaky Test Triage

Diagnose why a test fails intermittently and fix it. Graded: 5 consecutive passes + correct root cause.

6 train + 1 held-out
🔧

Toy Bug Fix

Fix an arithmetic bug so its test passes. Smoke/plumbing family for end-to-end validation.

6 train + 2 held-out

Key Design Decisions

🎯 Execution-Grounded Reward

task_success comes from running pytest, not an LLM judge. The reward is a fact about executed code.

🛡️ Held-Out Validation Gate

A candidate experience cannot influence behavior until it demonstrably improves performance on held-out variants. Anti-self-delusion.

💸 Free / Open Only

Both roles route to models that cost nothing. Local Ollama out of the box, free-tier hosted as an option. 4GB VRAM minimum.

📊 Compounding Curves

The metric is the slope of success over accumulated episodes — not a single benchmark score. Learning compounds.

🧠 Causal, Not Surface

The diagnoser infers why failure occurred (root cause + counterfactual repair), not just that it failed.

🗑️ Controlled Forgetting

Experience decays without reinforcement. Contradicted lessons lose confidence. Stale items get revalidated. No infinite rule accumulation.

Quickstart

Install & test (no GPU needed)
pip install -r requirements.txt
pytest                              # 167 tests, no model needed
Dry run — full pipeline, stub model (flat curves)
python run.py --family bug_reproduction --configs a0 a1 a2 \
    --seeds 1 2 3 --provider dry_run
Real learning curves (requires Ollama + 4GB VRAM)
ollama pull qwen2.5:3b-instruct

python run.py --provider config --family bug_reproduction \
    --n-episodes 28 --checkpoint-every 7 --max-steps 3
